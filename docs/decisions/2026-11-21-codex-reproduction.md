Question: how drawn reviewers independently reproduce disputed checks (source access, where it runs, what is reproduced, voting, first version). Asked once; Claude then reconciled; the joint decision is THIET-KE-NGHE-NHUNG.md §14.

## Proposed step 2

Treat reproduction as **independent evidence**, not a new oracle. A confidential VM can reduce who sees source, but it cannot by itself prove that arbitrary untrusted code ran honestly. The first version should say what it trusts—and what it does not.

1. **Source delivery:** Have the worker’s box export a minimal bundle containing the disputed commit and required build inputs, then encrypt it to a fresh, attested **builder-job key**, not to reviewers’ boxes. The builder verifies the commit and tree hashes against the claim before running anything. Do not include unrelated history, credentials, or secrets. This avoids giving more parties source access than necessary, though the client must still accept that the cloud TEE processes it. A client-sealed read-only token is a fallback if the worker cannot supply a verifiable bundle—not the default, since it requires client cooperation and exposes access to more boxes. Record the source and bundle hashes in the result.

2. **Where it runs:** Each reviewer can request a fresh, disposable confidential VM from a small, auditable launcher. The launcher image and job protocol are pinned and attested; the VM gets the bundle and runs the checks as an unprivileged user, without network access or secrets. A root supervisor records the command, exit status, logs, and hashes, then signs the result with a job key unavailable to the build process. Bind the signature to the commit, check-set, builder-image digest, and a fresh job nonce; publish the attestation and signed result for reviewers to verify. Destroy the VM and key afterward.

   This protects source from box owners under the TEE’s threat model and prevents an ordinary build process from simply signing a fabricated result. It **does not** make the supervisor infallible: a kernel exploit, TEE flaw, or side channel could undermine it. Without a hardware-enforced boundary around the build (for example, a supported nested VM), do not claim protection against all malicious build code. Reviewers’ boxes only verify evidence and vote; they never run the client’s code.

3. **What to reproduce:** Start with a short, explicit list of **brief-declared commands** in a pinned toolchain image—not a claim to emulate the client’s entire CI platform. Include commands, dependencies, timeout/resource limits, and expected outcomes in the brief before work begins. Reproduce only checks that can run without secrets or special hardware. Mark secret-dependent, hardware-dependent, or service-dependent checks **not independently reproducible**; do not substitute fake credentials or silently weaken them. A later version can add documented CI-runner emulation where needed.

4. **Voting:** Reviewers verify the attestation, commit, check-set, and image digest, then weigh the reproduced outcome alongside the client CI evidence and brief. Matching failures support rejecting the claim; matching passes support it, but are not conclusive if environments differ. A mismatch or impossible run is **inconclusive**, not automatically a pass or fail. Reviewers state reasons and may vote based on the remaining evidence. Keep the existing 14-day settlement rule for unresolved disputes.

5. **Minimal first version:** Implement one pinned builder image, one fixed set of secret-free declared checks, bundle hash verification, unprivileged execution, signed results, and a documented evidence format. Start one builder per disputed claim; record that this is *a* reproduction, not a majority of independent builds. Fund and launch it through a capped dispute budget, paid from an agreed protocol fund or dispute bond—not an unpaid reviewer’s personal cloud account. Leave multiple independent builders, broader CI emulation, hardware isolation from kernel exploits, and secret-dependent checks for later. If no budget or eligible builder is available, report “not reproduced” and use the current dispute rules rather than pretending reproduction occurred.
